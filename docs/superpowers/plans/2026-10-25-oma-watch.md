# Ома-прораб, план 2: сторож, herdr и Orca, восстановление работы — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** раз в минуту Ома проверяет здоровье всех агентов (лимиты, связь, зависание, падение, ошибки API, забытые вопросы, долгое ожидание помощника), сама восстанавливает работу через терминал агента в herdr или Orca, подсказывает агентам про лимит фактами через хук и будит их после сброса; пользователю говорит коротко и склеено, срочное — всегда, кроме тихого режима.

**Architecture:** демон на Rust. Терминалы агентов — за адаптерами `src/mux/` (трейт `Mux`, реализации Orca и herdr; ядро знает только трейт). Правила сторожа — чистая логика `src/watch.rs`: на вход факты об агентах, на выход — действия (`Act`). Факты собирает демон из реестра, хвоста транскрипта и `/proc`. Действия в терминале выполняет отдельный поток (`mux::spawn`), чтобы вызовы CLI не держали цикл событий. Прогноз лимита — `src/limits.rs`: проценты из строки статуса Claude Code (обёртка `agent-speak statusline`) и из rollout Codex. Подсказки агентам — файлы на сессию, их отдаёт хук `PostToolUse` (`agent-speak hook post-tool-use`). Речь сторожа — готовые фразы из кода на доске новостей (классы `Urgent` и `Restore`). Оценка «завис ли долгий вызов» — Haiku через тот же `digest` (`Ask::Hung`).

**Tech Stack:** Rust (serde_json, libc — уже в Cargo.toml), CLI `orca` (Orca 1.4.237) и `herdr` (0.9.1), Python 3 (voice-venv), QML/JS плагина.

**Spec:** `docs/superpowers/specs/2026-10-24-oma-foreman-design.md` — разделы «Лимиты: умная остановка», «Сторож», «Основа: herdr через адаптер», «Мои решения»; пример с пятью агентами. Задания агентам голосом, ответы агентам, запуск новых агентов, подтверждение опасного — план 3.

### Доделки по вопросам пользователя (2026-10-25)

- **Снимок.** Сделан: `plugin/preview.png`, постановка с выдуманными агентами (подставной сокет демона на минуту), оранжевый орб и строки здоровья. Оболочка с 02:32 держала старые `Model.js` и `Window.qml`: перезагрузка плагина по изменению файлов не сбросила кэш. Помог `omarchy restart shell`.
- **`statusLine` и Orca.** Orca переписывает `statusLine` не только при обновлении, а при каждом своём запуске: команда со строкой `agent-hooks/claude-statusline.sh` для неё «своя» (`installManagedStatusLine`). Обёртка переехала в managed-настройки Claude Code (`/etc/claude-code/managed-settings.d/agent-speak.json`, старше пользовательских). `agent-speak statusline` без аргументов зовёт `statusLine` из `~/.claude/settings.json`, а там снова команда самой Orca. Пользователь отверг опрос настроек раз в минуту как костыль.
- **Попытки.** Предел прежний: 3 за час. Сдаётся Ома теперь не насовсем: сказав «поднять не получилось», она пробует снова, когда старая попытка выйдет из часа. Окно в 15 минут не взяли: при пороге 12 минут три зависания длятся не меньше 36 минут, и предел перестал бы действовать.
- **Просьба про помощника.** Агент не отозвался за `hung_after` — срочный зов пользователя. Ома замолкала только об этом агенте и только до его следующего движения, но без зова агент мог стоять, пока пользователь не заглянет.
- **Подсказка про лимит.** Форма «сброс через N мин» осталась, её выбрал пользователь. Текст пишется заново каждый тик, а не замораживается в начале эпизода: сабагент читает его позже главного, и минуты должны быть верными.
- **Orca внутри herdr.** Работает без правок: терминал засчитывается по хозяину (pty-хост Orca), а не по порядку адаптеров.
- **Вне мультиплексора.** Срочное «завис, перезапусти сам» — только после вердикта модели, как у всех: долгая сборка в обычном окне терминала больше не тревожит.
- **Недонабранное.** Перед каждым текстом в терминал агента или оболочки уходит Ctrl+U (`mux::perform`): в Claude Code это «удалить до начала строки», вернуть — Ctrl+Y, в bash и zsh — так же. Проверено в пробной сессии herdr: черновик в bash и в поле Claude Code стёрт, остался только текст Омы. В Orca Ctrl+U идёт тем же `send --text`, что и проверенный Esc. Многострочный черновик Claude Code стирается только в своей последней строке.
- **Вывод CLI.** Процесс вышел, а его вывод держит потомок — чтение ждёт не дольше общего таймаута и возвращает ошибку.
- **Гистерезис прогноза.** Хороший прогноз при окне, ещё стоящем у порога, кончает эпизод лимита через 10 минут (`LIMIT_HOLD`), а не сразу: пауза агента больше не стирает подсказки и метки «прочитано». Сброс окна кончает эпизод сразу.

## Решения этого плана

Спека оставила их строителю или их решил пользователь 2026-10-25.

- **Оба адаптера.** Агенты пользователя живут в Orca, herdr не запущен. Пользователь выбрал оба адаптера: Orca (MIT) и herdr (Apache-2.0), через один трейт. Терминал агента находится по окружению его процесса (`/proc/<pid>/environ`): Orca — `ORCA_TERMINAL_HANDLE` и `ORCA_CLI_BIN_DIR`; herdr — `HERDR_PANE_ID` и `HERDR_SOCKET_PATH`. Интеграция herdr (`herdr integration install claude`) не нужна: если herdr не распознал агента, текст уходит через `pane run`.
- **Сторож и действия — в демоне.** Модель только оценивает зависание долгого вызова.
- **Пороги по умолчанию.** Сторож — раз в 60 с (`watch_every`). «Завис» — 12 мин тишины (`hung_after`): Bash в Claude Code сам обрывается через 10 мин, 12 мин его не спутают с зависанием. Напоминание о вопросе — раз в 15 мин (`remind_after`). Порог лимита — 95 % (`limit_threshold`).
- **Прогноз лимита.** Темп считается по замерам за последние 15 мин, нужен размах замеров от 2 мин. Время до конца — `(100 − %) / темп`. Прогноз плохой, если `% ≥ порога` и лимит кончится раньше сброса. Темп ≤ 0 — прогноза нет, Ома молчит.
- **«Встал по лимиту» и «закончил ход».** Подсказка просит агента, остановившегося из-за лимита, закончить ответ строкой «Остановился по лимиту». Конец хода с этой строкой означает, что агент встал по лимиту. Вторая причина: последняя запись транскрипта — ошибка API `rate_limit`. После сброса +60 с Ома будит обоих.
- **Подсказка — один раз за эпизод.** Файл `$XDG_RUNTIME_DIR/agent-speak-hints/<session>`. Текст пишется заново каждый тик, минуты в нём относительные. Хук отдаёт текст один раз главному агенту и один раз каждому сабагенту (метка `<session>.<agent_id|main>.seen`). Прогноз стал хорошим или лимит сброшен — файлы удаляются.
- **Лестница при зависании.** Сначала Esc и сообщение «продолжай». Если тишина держится ещё `hung_after/2`, Ома шлёт Ctrl+C дважды: агент выходит, и дальше работает путь «упал». Если и после перезапуска агент висит, звучит срочное «поднять не получилось». Любая активность агента после действия Омы сбрасывает лестницу.
- **Оценка модели.** Вызов инструмента или поток ответа молчат `hung_after`. Тогда Haiku получает последний вызов и экран терминала и отвечает: висит или работа долгая по природе (сборка, тесты, сон, ожидание сервера, повтор запроса на экране). Ответ «долгая» откладывает вопрос ещё на `hung_after`. Без модели и при тишине от `3 × hung_after` агент считается зависшим. Сабагент (`Agent`/`Task`), молчащий вместе с родителем, считается зависшим без модели.
- **Опасно или непонятно — не трогать.** Bash с push, `rm`, `git reset`, force, миграцией, деплоем, записью в базу — не трогать, срочно спросить пользователя. Инструмент MCP, чьё имя не начинается с get/list/read/search/find/query/fetch/describe/show, — тоже. Незнакомый инструмент — тоже.
- **Упал или закрыли.** Процесс агента исчез, а агент был «работает». Если его родитель — оболочка, она жива и детей у неё нет, Ома набирает в этом терминале команду возобновления с флагами пользователя. Условие: пользователь не трогал ввод 60 с, или агента закрыла сама Ома. Если пользователь был за компьютером, он, скорее всего, закрыл агента сам, и Ома только сообщает. Флаги — белый список, позиционный промпт исходной команды не повторяется.
- **Связь.** Последняя запись — `server_error`, агент не работает, с ошибки прошло от 60 с. Ома просит агента продолжить, не больше 3 раз за 30 мин, дальше — срочное «связь не держится».
- **Codex.** Его проценты из rollout идут в прогноз, проверки «завис» и «упал» работают по mtime rollout. Ошибки API, вызов в полёте и помощники у Codex не разбираются. Хук подсказки у Codex подключается вручную, это в README (shortcut).
- **Сигнал орба** — режим `trouble`: оранжевый, иконка-треугольник с «!», выше «ждёт ответа». Число агентов с нерешённой срочной проблемой — поле `trouble` строки состояния. Строка агента в окне показывает `health`, мозг Омы видит его в инструменте `agents`.

## Global Constraints

- Новых зависимостей нет ни в `Cargo.toml`, ни в voice-venv, ни в плагине.
- Ядро (`watch.rs`, `daemon.rs`) не знает команд и форматов Orca и herdr: всё это — в `src/mux/orca.rs` и `src/mux/herdr.rs`.
- Вызовы CLI мультиплексоров — только в потоке действий, с таймаутом 10 с, никогда в цикле событий.
- Жёстко не прерывать и не убивать из-за лимита: Ома только сообщает факты.
- Не трогать агента посреди опасного или непонятного вызова.
- Агенту не уходит текст, о котором пользователь не узнал: каждое действие в терминале кончается фразой пользователю (пузырь и, вне тишины, доска).
- «Всё в порядке» сама Ома не говорит: о здоровье — только по изменению и на вопрос (инструмент `agents`).
- Тихий режим: ни звука, пузыри остаются. `agents_voice = false`: сторож выключен целиком — ни действий, ни подсказок (файлы подсказок удаляются), ни речи.
- Срочное (`Class::Urgent`) звучит и когда пользователь «занят», но не когда его «нет на месте», и не в тишине.
- Без модели сторож работает целиком: все фразы — из кода, зависание — по порогу `3 × hung_after`.
- В речи нет имён переменных, функций, файлов, путей, команд. В подсказках агенту — можно.
- Комментарии: в Rust и Python — по-русски, в QML и JS плагина — по-английски; одна строка «почему».
- Коммиты — без ИИ-соавторов и подписей «Generated with…».
- Проверка: `cargo test`; Ома — `~/.local/share/agent-speak/voice-venv/bin/python -m pytest python/test_agent_voice.py`; плагин — `node plugin/test.js`. `cargo build` без предупреждений.
