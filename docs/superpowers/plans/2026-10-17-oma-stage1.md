# Ома, этап 1 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ома — заместитель над агентами пользователя. Орб с пузырями висит поверх окон. Окно по центру показывает сводку агентов и чаты. Ома отвечает на личные вопросы голосом и текстом, умеет постоянный диалог и тихий режим.

**Architecture:**
- **Демон `agent-speakd` (Rust).**
  - Ведёт реестр живых агентов пользователя по трём источникам: `~/.claude/sessions/*.json`, процессы `codex` и хуки.
  - Рассылает подписчикам три вида строк: состояние, агентов и пузыри.
  - Решает, что звучит: диалог, тихий режим, удержание звука за Омой.
  - Держит всегда запущенный процесс Омы (`python -m agent_voice`). Команды плагина передаёт ему в stdin, его события рассылает подписчикам.
- **Процесс Омы.**
  - Слух: `pw-record` → Silero VAD → whisper. От сети модель держится тёплой, от батареи грузится по требованию.
  - Машина разговора: фраза по клику с черновиком или постоянный диалог.
  - Мозг: сессия Claude Agent SDK на каждый чат. Свои инструменты: агенты, лента, хвост переписки, выделение.
- **Плагин `predmaxim.agent-speak`** становится панелью `keepLoaded`: орб с пузырями на слое Top и окно по центру.

**Tech Stack:**
- Rust 2024: serde, toml, notify, libc.
- Python 3.12 (voice-venv): faster-whisper, silero-vad, claude-agent-sdk 0.2.163.
- Quickshell QML: `qs.Commons`, `qs.Ui`, `Quickshell.Wayland`, `Quickshell.Hyprland`, `QtQuick.Effects`.
- node — для `plugin/test.js`.

**Spec:** `docs/superpowers/specs/2026-10-17-oma-stage1-design.md`

## Global Constraints

**Рабочее место и коммиты**
- Работа идёт в отдельном worktree `~/Projects/omarchy/own/agent-speak-oma`, ветка `oma`. Причина: `plugin/` и `python/agent_voice` в `~/Projects/omarchy/own/agent-speak` — живые ссылки, и правки там сразу видит работающая система. В `main` ветка вливается только в Task 13, с пользователем.
- Коммиты без ИИ-соавторов. `impl` не пушить. Ничего личного в коде и тестовых данных.
- Комментарии и сообщения в коде — по-русски. В плагине — английские ключи с русской таблицей в `I18n.js`, и каждая новая строка попадает в таблицу.

**Поведение Омы**
- Ответ Омы — одна-три фразы, без вступлений, markdown и списков. Звучит и показывается один и тот же текст.
- Права Омы — только чтение. Встроенные инструменты: только `Read`, `Glob`, `Grep`, `WebSearch`, `WebFetch`. Свои: `mcp__oma__agents`, `mcp__oma__agent_feed`, `mcp__oma__agent_tail`, `mcp__oma__selection`.
- Сводка показывает только сессии пользователя:
  - Claude — `kind` ∈ {`interactive`, `bg`}, `entrypoint == "cli"`, pid жив;
  - Codex — процесс `codex`, в cmdline нет `exec` и `app-server`.

**Звук**
- Тихий режим глушит всё, кроме явного чтения по хоткею (`Read`) и образца голоса (`Preview`). Это прочтение анти-цели «звук без спроса» — сообщить пользователю при сдаче.
- Статусы и финалы агентов (`Status`, `Manual`) звучат только в постоянном диалоге.
- Срочное (`Urgent`) и ответы Омы (`Voice`) звучат всегда, кроме тихого режима.
- Пока Ома думает или говорит, демон удерживает в очереди фразы агентов.

**Пузыри**
- Не больше трёх. Ключ слияния — `id`.
- Вне тихого режима стопка гаснет через 10 000 мс после последнего пузыря. В тихом режиме висит до клика.

**Тихий режим и слух**
- Тихий режим по умолчанию 23:00–08:00, расписание включено. Ручное переключение (`quiet_override`) снимается на ближайшей границе расписания.
- Whisper от сети загружен всегда. От батареи грузится по первому включению слуха и выгружается после 300 с без слуха.

**Окно, ключи, деплой**
- Окно по центру: ширина `min(Style.space(900), ширина − Style.space(80))`, высота `min(Style.space(600), высота × 0.85)`. Вид — по `~/omarchy-dotfiles/docs/rules.md` §9 (скилл `omarchy-plugin-ui`). Namespace `predmaxim-agent-speak`: он уже в `no_anim`.
- Процессы Омы получают `AGENT_SPEAK=1`: хуки их сессий не доходят до демона.
- Ключи чатов:
  - `"new"` — ещё не созданный общий;
  - `"chat:<sdk id>"` — общий;
  - `"agent:<id сессии агента>"` — чат агента.
- Чат агента привязан к сессии агента, а не к папке: у пользователя многие агенты работают в одной `~/Work`. Это уточнение спеки «один на проект» — сообщить при сдаче.
- Деплой (слияние в `main`, `./install.sh`, перезапуск оболочки) обрывает озвучку и меняет живую систему. Только с пользователем.
- Живая проверка интерфейса — только через IPC и `grim`. Окно с захватом клавиатуры не открывать, не спросив «руки убрал?».

## Протокол сокета

Подписчик получает сначала строку состояния, затем строку агентов. После этого — любые строки ниже.

```
{"running":true,"speaking":false,"paused":false,"read_intermediate":true,"speaker":"xenia","rate":"medium","project":"","oma":"off","dialog":false,"quiet":false,"quiet_schedule":true,"quiet_from":"23:00","quiet_to":"08:00","orb_corner":"bottom-right","waiting":0}
{"agents":[{"id","agent","title","project","cwd","transcript","state","status","since","focused","feed":[{"at","kind","text"}]}]}
{"bubble":{"id","who","text","kind","append","drop"}}     kind: status | question | final | oma | draft
{"chat":{"key","was","messages":[{"role":"me|oma","text"}]}}  was — прежний ключ ("new"), когда чат получил id
{"chat_delta":{"key","role","text"}}
{"chats":[{"key","title","updated"}]}
```

Состояния агента: `working`, `waiting`, `done`, `idle`. Поле `oma`: `off`, `idle`, `loading`, `listening`, `thinking`, `speaking`, `paused`.

**Команды демону:**
- от плагина и CLI: `{"cmd":"oma","action":{…}}`. Демон пишет `action` строкой в stdin Омы. Возможные `do`:
  - `talk`, `send`, `cancel`, `dialog`, `new`, `chats`;
  - `{"do":"ask","text","key"}`;
  - `{"do":"open","key"}`;
- от Омы:
  - `{"cmd":"voice","text"}`;
  - `{"cmd":"voice_state","state","dialog"}`;
  - `{"cmd":"stop"}`;
  - `{"cmd":"emit","line":{…}}` — демон рассылает `line` как есть.

## Review Focus

1. **Демон перезапущен или упал.** Ома выходит по EOF stdin, `pw-record` и `claude` не остаются сиротами. Если упала сама Ома, демон поднимает её через 10 с, а не в цикле. Тесты: Task 4 `dead_oma_respawned_after_backoff`, Task 9 `test_watch_ignores_unknown_lines_and_eof_ends`.
2. **Лишние записи в `~/.claude/sessions/`.** Устаревшие записи с мёртвым pid, SDK-сессии самой Омы (`sdk-cli`) и ключи `*.key` не попадают в сводку. Тест: Task 2 `scan_keeps_only_live_user_sessions`.
3. **Граница расписания.** Ручное переключение снимается ровно на границе, а не каждую секунду. Расписание работает через полночь. Тесты: Task 1 `quiet_window_wraps_midnight`, Task 4 `override_cleared_at_schedule_boundary`.
4. **Клик по орбу, пока звучат Ома или статусы.** Звук обрывается, черновик не теряется, ответ Омы не перемежается статусами агентов. Тесты: Task 6 `test_click_while_speaking_interrupts_and_listens`, `test_statuses_audio_does_not_end_draft`; Task 4 `hold_skips_agent_speech_until_released`.
5. **Новые типы строк сокета.** Они не ломают разбор: незнакомая строка игнорируется, строка состояния приходит первой. Тесты: Task 3 `subscribe_sends_state_then_agents`, Task 10 `parseLine`, Task 9 `test_watch_ignores_unknown_lines_and_eof_ends`.

```rust
pub const FEED_MAX: usize = 20;     // строк ленты на агента
pub const LINE_MAX: usize = 300;    // символов в строке ленты
pub const IDLE_AFTER: u64 = 600;    // с после «готово» → «простаивает»

#[derive(Clone, Copy, Debug, PartialEq, Serialize)] #[serde(rename_all = "lowercase")]
pub enum State { Working, Waiting, Done, Idle }

#[derive(Clone, Debug, Serialize)]
pub struct Line { pub at: u64, pub kind: &'static str, pub text: String } // prompt | status | question | final

#[derive(Clone, Debug, Serialize)]
pub struct Entry { pub id: String, pub agent: &'static str, pub title: String, pub project: String, pub cwd: String,
    pub transcript: String, pub state: State, pub status: String, pub since: u64, pub focused: bool,
    pub feed: VecDeque<Line>, #[serde(skip)] pub heard: bool }

#[derive(Clone, Debug)]
pub struct Live { pub id: String, pub agent: &'static str, pub pid: u32, pub title: String, pub cwd: String,
    pub transcript: PathBuf, pub busy: bool }

pub fn scan_claude(sessions: &Path, projects: &Path, alive: impl Fn(u32) -> bool) -> Vec<Live>;
pub fn scan_codex() -> Vec<Live>;
pub fn scan_all() -> Vec<Live>; // ~/.claude/sessions + ~/.claude/projects, живость — /proc/<pid>, плюс codex

impl Registry {
    pub fn new() -> Registry;
    pub fn sync(&mut self, live: Vec<Live>, now: u64) -> bool; // true — состав изменился
    pub fn get(&self, id: &str) -> Option<&Entry>;
    pub fn prompt(&mut self, id: &str, text: &str, now: u64) -> bool;   // false — не наш агент
    pub fn status(&mut self, id: &str, text: &str, now: u64) -> bool;
    pub fn question(&mut self, id: &str, text: &str, now: u64) -> bool;
    pub fn finished(&mut self, id: &str, text: &str, now: u64) -> bool;
    pub fn tick(&mut self, now: u64) -> bool;                // done старше IDLE_AFTER → idle
    pub fn set_focused(&mut self, id: Option<&str>) -> bool;
    pub fn waiting(&self) -> usize;
    pub fn line(&self) -> String; // "{\"agents\":[…]}\n"
}
```

- Правила `scan_claude`:
  - файлы `*.json` с `kind` ∈ {`interactive`, `bg`}, `entrypoint == "cli"`, `alive(pid)`;
  - `title` = `name`, если `nameSource != "derived"` и имя не пустое, иначе имя папки `cwd`;
  - `transcript` = `projects/*/<sessionId>.jsonl`, первый найденный, иначе пусто;
  - `busy` = `status == "busy"`.
- `sync` для нового агента ставит `Working`, если `busy`, иначе `Idle`. Пока агент не услышан хуком (`heard == false`), повторная синхронизация обновляет его состояние из `busy`. После первого хука файл состояние не меняет.
- `status` и `prompt` → `Working`. `question` → `Waiting`. `finished` → `Done`, при этом `status` = первое предложение ответа (до `.`, `!`, `?`, `…`, не длиннее 120 символов).
- Каждое событие пишет строку ленты (не длиннее `LINE_MAX` символов, в ленте не больше `FEED_MAX` строк) и `since = now`.
- Порядок `line()`: `waiting`, `working`, `done`, `idle`; внутри группы — по `since`, свежие первыми.
- `focus.rs`:
  - `pub fn codex_rollout(pid: u32) -> Option<(String, PathBuf)>` — вынесен из `codex_under`;
  - `pub fn is_user_codex(cmdline: &str) -> bool` — аргументы через `\0`, без `exec` и `app-server`;
  - `pub fn project_of` сделать `pub`.
- `claude.rs`: `pub fn last_question(content: &str) -> Option<String>` — если самый поздний `tool_use` в транскрипте — `AskUserQuestion`, вернуть его `input.questions[0].question`, иначе `None`.

#[test]
fn states_follow_hooks() {
    let mut r = Registry::new();
    assert!(r.sync(vec![live("a", true), live("b", false)], 100));
    assert_eq!((r.get("a").unwrap().state, r.get("b").unwrap().state), (State::Working, State::Idle));
    assert!(r.question("a", "Клод задал вопрос: какой вариант?", 110));
    assert_eq!((r.get("a").unwrap().state, r.waiting()), (State::Waiting, 1));
    assert!(r.status("a", "Читаю план.", 120));
    assert_eq!(r.get("a").unwrap().state, State::Working);
    assert!(r.finished("a", "Готово. Тесты прошли, PR создан.", 130));
    r.sync(vec![live("a", true), live("b", false)], 131); // файл сессии не перебивает хуки
    let a = r.get("a").unwrap();
    assert_eq!((a.state, a.status.as_str(), a.since), (State::Done, "Готово.", 130));
    assert!(!r.tick(130 + IDLE_AFTER - 1));
    assert!(r.tick(130 + IDLE_AFTER));
    assert_eq!(r.get("a").unwrap().state, State::Idle);
    assert!(r.prompt("a", "запусти тесты", 900));
    assert_eq!(r.get("a").unwrap().feed.back().unwrap().kind, "prompt");
    assert!(!r.status("чужой", "текст", 1));
}

fn drain(r: &mut BufReader<UnixStream>) -> Vec<serde_json::Value> {
    let mut out = vec![];
    let mut l = String::new();
    while r.read_line(&mut l).is_ok_and(|n| n > 0) { out.push(serde_json::from_str(&l).unwrap()); l.clear(); }
    out
}

fn bubbles(r: &mut BufReader<UnixStream>) -> Vec<serde_json::Value> {
    drain(r).into_iter().filter_map(|v| v.get("bubble").cloned()).collect()
