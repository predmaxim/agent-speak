# agent-speak — озвучка ИИ-агентов в реальном времени

Дата: 2026-10-02. Статус: проект, ждёт одобрения.

## Зачем

Ответы агентов (Claude Code, Codex) удобнее слушать, чем читать, — но только если озвучка идёт **по ходу работы**: промежуточные статусы звучат сразу, как агент их написал, а не одним куском в конце. Нынешний bash-скрипт (`omarchy-dotfiles/home/.local/bin/agent-speak`) этого не умеет и медленный: на каждое чтение заново стартуют `claude -p` (переписывание всего ответа, ~6 с) и Silero (~2 с загрузки).

Критерии успеха:

- промежуточный статус агента звучит через ~1 с после появления на экране;
- английские термины, числа, пути читаются осмысленно, код и markdown — нет;
- озвучка не мешает: молчит, когда пишешь или диктуешь, ставится на паузу, говорит только про окно в фокусе;
- агенты не тормозят из-за хуков.

## Решения, принятые в обсуждении

- Свой сервис, а не готовый проект: ни один из изученных (agent-tts-macos, claude-code-narrator, melderan/claude-code-tts, agentlabs-voice, HalbonLabs/agent-voice и др.) не готовит текст под русский синтезатор и не умеет Hyprland. Приёмы из них заимствованы — отмечены ниже.
- Сервис на **Rust**, синтез — постоянный процесс на **Python** с Silero (модель только для PyTorch; через ONNX русского Silero v5 с ударениями нет, libtorch в Rust — 2 ГБ и переписывание предобработки).
- Голос — Silero v5 (`v5_ru.pt`), ударения и «ё» ставит сам Silero.
- ИИ не стоит на пути к звуку: только пополняет словарь терминов в фоне (вариант «гибрид»).
- Агент сам текст для озвучки не готовит (дорого, шумно, ненадёжно) — по желанию одна строка в правилах агентов «статусы — простыми фразами без markdown».

## Компоненты

```
 Claude Code ──хуки──┐                       ┌─────────── agent-speakd (Rust, systemd --user) ───────────┐
 Codex ──notify──────┤   agent-speak hook    │  источники → дедуп → очистка → термины → очередь → звук   │
                     ├──────────────────────▶│      ▲ транскрипты          словарь       │ текст  ▲ PCM  │
 хоткеи Hyprland ──▶ agent-speak read|stop|  │                                           ▼        │      │
                     pause|mode ────────────▶│                          silero-tts (Python, сокет)      │
                                             └───────────────────────────────────────────────────────────┘
```

1. **`agent-speakd`** — сервис (`systemd --user`, `agent-speakd.service`). Источники, дедуп, подготовка текста, словарь, очередь, звук. Запускает `silero-tts` дочерним процессом и перезапускает при падении.
2. **`silero-tts`** — Python, ~60 строк. Модель в памяти; по unix-сокету принимает `{text, speaker, rate}` и отдаёт PCM s16 48 кГц моно. Venv и модель — `~/.local/share/agent-speak/` (уже установлены).
3. **`agent-speak`** — тот же бинарник как команда: `hook <kind>` (JSON хука из stdin), `read`, `stop`, `pause`, `mode`. Шлёт одно сообщение в сокет сервиса (`$XDG_RUNTIME_DIR/agent-speak.sock`) и выходит.

Репозиторий — `~/Projects/agent-speak` (`predmaxim/agent-speak`). В `omarchy-dotfiles` остаются хоткеи и ссылка на бинарник; нынешний bash-скрипт удаляется, когда новый сервис заработает.

## Источники текста

### Claude Code

| Источник | Что даёт | Зачем |
|---|---|---|
| хук `MessageDisplay` | текст кусками в момент вывода на экран, `message_id` | реальное время: из кусков собираются законченные предложения и сразу идут в очередь |
| транскрипт `~/.claude/projects/*/<session>.jsonl` (inotify, смещение на файл) | блоки `text` и блоки `thinking`, у которых в base64-декоде `signature` есть `narration` (так Claude Code пишет часть промежуточных сообщений; проверено на этой сессии) | только ручное чтение и финальный ответ (`Stop` без промежуточных); вживую не читается |
| хук `Stop` | конец хода | дочитать неполное предложение |
| хук `UserPromptSubmit` | пользователь отправил сообщение | стоп и очистка очереди этой сессии |
| хук `Notification` | агент ждёт разрешения/ответа | срочная фраза |

Формат `MessageDisplay` известен только по чужому скрипту (cg_cct, `tts-messagedisplay-hook.sh`: `delta`, `final`, `message_id`). Первый шаг реализации — записать реальные события хука. Если нужного в нём нет, источник реального времени — транскрипт (замеренная задержка 0,1–0,5 с).

### Codex

Rollout `~/.codex/sessions/*/*/*/rollout-*.jsonl` (inotify): все `response_item` / `message` с `role: assistant` (задержка 0,02–0,1 с). `notify` в `~/.codex/config.toml` — конец хода. Сабагенты Codex отсеиваются по `thread_source` в первой строке rollout (приём agent-tts-macos).

### Повторы

1. Claude вживую читается только из хука `MessageDisplay`, транскрипт в этом режиме пропускается: `message_id` хука — UUID, в транскрипте `msg_…`, они не совпадают; тексты тоже (хук режет на предложения, `narration` — перефразировка), поэтому связать и отсеять дубли нельзя.
2. Хэш нормализованной фразы (нижний регистр, без пробелов и пунктуации) на сессию — точные повторы не читаются (приём agent-tts-macos).

### Какие сессии говорят

Окно в фокусе → сессия: `hyprctl activewindow` → pid окна → потомок из `~/.claude/sessions/<pid>.json` (Claude) или процесс `codex` с открытым rollout (Codex).

- **Авто**: озвучивается одна *активная* сессия — агент, на окне которого фокус простоял ≥ 5 с (окна не-агентов не в счёт, `read` переключает сразу). Её статусы звучат вживую; статусы остальных выбрасываются (и при смене активной, и если за ними уже стоит финал той же сессии). Финальные ответы неактивных сессий (Stop `last_assistant_message`, Codex notify) ждут в очереди и звучат, когда сессия станет активной; возврат к сессии продолжает её очередь. Срочные — из любой сессии сразу, с префиксом проекта («Astral: нужно разрешение»). Смена активной не обрывает фразу; сообщение человека в сессии X обрывает только речь X.
- **Вручную**: `read` (границы хода — сообщение человека или `queued_command`; служебные записи вида `<task-notification>`, `Caveat:` ход не рвут) читает весь последний ход окна в фокусе (с промежуточными текстами) из транскрипта; пока агент пишет — текущий ход до этого момента.

## Подготовка текста

Предложение за предложением, без ИИ:

1. **Очистка**: блоки кода — выбросить; путь в `` ` `` → имя файла (`file.rs:42` → «file.rs»); URL → домен; строка таблицы → «a, b, c»; пункт списка → предложение; markdown, эмодзи — убрать; `→` → «в»; короткий `` `код` `` остаётся и идёт как термин.
2. **Выброс обрывков**: вырезанное место помечается; предложение с ≥2 пометками или с пометкой и <3 оставшимися словами не читается (короткое целое «Готово.» читается) (приём beltranrengifo/agent-voice, `_drop_gutted_sentences`).
3. **Числа словами**: целые, десятичные, версии («два точка один точка двести восемьдесят четыре»), проценты. Ограничение: именительный падеж («в три файлах») — склонение правилами не надёжно.
4. **Термины**: каждое латинское слово ищется в `~/.local/share/agent-speak/terms.tsv` (`слово<TAB>произношение`, регистр не важен, `+` — ударение). Нет в словаре — сразу читается по правилам: аббревиатура до 4 букв по буквам («эн-пи-эм»), остальное — транслитерацией; слово ставится в фоновую очередь модели. Фон: пачками до 20 слов, самая лёгкая модель агента (`claude -p --model haiku`, `MAX_THINKING_TOKENS=0`, без MCP/инструментов/памяти; для Codex — быстрая модель из `models_cache.json`), ответ дописывается в словарь. Стартовый словарь — ~50 терминов в репозитории, ставится при установке, если файла нет.
5. **Ударения и «ё»** — Silero (`put_accent`, `put_yo`).

## Воспроизведение

- **Очередь** в памяти сервиса. Фраза: сессия, вид (обычная/срочная), время появления. Обычная старше 30 с (настройка) выбрасывается; срочные — в начало. Начатая фраза договаривается; новая её не обрывает (agentlabs-voice отказался от обрыва).
- **Синтез наперёд**: пока звучит фраза, готовятся 1–2 следующие (melderan `next_speakable`).
- **Звук**: один постоянный `pw-cat --playback --raw` (s16, 48 кГц, моно), PCM пишется в его stdin. Стоп — убить и перезапустить `pw-cat` (сброс буфера).
- **Пауза**: перестать писать в поток и перезапустить `pw-cat`; возобновление — с начала прерванного предложения. На паузе возраст фраз не растёт (melderan `PauseLedger`), новые копятся.
- Кэша звука нет: подготовка мгновенная, первая фраза синтезируется за ~0,5 с. Если повтор окажется медленным — добавить.

## Управление

| Команда | Хоткей | Действие |
|---|---|---|
| `read` | Super+Alt+R | весь последний ход окна в фокусе; если уже читает — стоп |
| `pause` | Super+Alt+P (проверить, что свободна) | пауза ↔ продолжение |
| `mode` | Super+Alt+Shift+R | авто ↔ вручную |
| `stop` | хук `UserPromptSubmit`, Home (диктовка) | стоп и очистка очереди |

Уведомления (`notify-send`): «нечего читать», «в фокусе нет агента», «синтез упал». Пофразовых уведомлений нет; режим, начало и остановку чтения показывает значок на панели.

Настройки — `~/.config/agent-speak/config.toml`: `mode` (`auto`/`manual`), `speaker` (`xenia`, `baya`, `kseniya`, `aidar`, `eugene`), `rate` (скорость речи), `max_age_secs` (30), `read_intermediate` (`true`; `false` — в авторежиме только финальный ответ в конце хода). Сервис перечитывает файл при изменении — им будет управлять отдельный интерфейс (следующий подпроект).

## Ошибки

- `silero-tts` упал — перезапуск; 3 неудачи подряд — уведомление «синтез упал», очередь ждёт.
- Сервис не запущен — `hook`, `stop`, `pause`, `mode` выходят с кодом 0 молча; `read` — строка в stderr, без уведомления.
- Модель словаря не ответила или ответила мусором (не кириллица) — слово остаётся с транслитерацией, повтор при следующей встрече.
- Недописанная строка транскрипта — пропускается, дочитывается при следующем изменении файла.
- Неожиданный формат хука — событие игнорируется, ошибка в журнал (`journalctl --user -u agent-speakd`).
