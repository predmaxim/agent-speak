# agent-speak

Озвучка ИИ-агентов (Claude Code, Codex) и голосовой заместитель **Ома**. Ома следит за агентами, которых запустил пользователь, коротко докладывает их состояние голосом и текстом, отвечает на вопросы, передаёт агентам ваши ответы и задания, запускает новых, а повисших и упавших агентов поднимает сама. Голос — Silero `v5_6_ru`, по-русски: предложение на «?» модель сама читает вопросом, на «!» — восклицанием. Текст готовится к чтению без ИИ на пути к звуку: код и markdown выбрасываются, пути (и относительные, `src/x.rs:120`) — имя файла, числа — словами (с ведущими нулями «0.05», разрядами «1 000» и временем «12:30»; список трёхзначных через пробел «100 200 300» пока читается одним числом; запятая — разряды только в «1,000» и «1,234,567», иначе десятичная, как «1,155»; падежи не склоняются), знаки, которых нет у Silero, — словами («×» — «на», «=» — «равно», «!=» — «не равно», «>=» и «<=» — «не меньше» и «не больше», «=>» — «в», «+» — «плюс»; «/» — граница слова, пробел, а не пауза; зачёркивание `~~` и подчёркивание заголовка `=====` — разметка, не читаются; «слово/имя.ext» с заглавной или файлом слева от «/» — перечисление «TypeScript/Node.js», а не путь), сокращения с точкой («т. е.», «т. к.», «см.», «напр.», «тыс.», «и т. д.») — полностью и не рвут предложение, английские термины — по словарю.

## Ома

- **Орб** — кружок поверх всех окон, и полноэкранных тоже (настройка «Над полноэкранными окнами» выключена — под ними). Клик — разговор с Омой, ПКМ — окно. Перетаскивается куда угодно; отпущенный у угла (ближе ~64 px) защёлкивается в угол, у края вне угла остаётся где отпущен; место запоминается.
- **Состояния орба** — цвет и тонкая иконка в центре, из одного в другое орб перетекает плавно: плоский градиент акцента темы — покой; зелёно-жёлтый с микрофоном, плывёт и дышит — слушаю; жёлтый с мозгом, кружится — думаю; синий с динамиком, пульсирует — говорю; как покой, с паузой — пауза (микрофон занят другой программой); красный с «?» — агент ждёт ответа; оранжевый с треугольником «!» — сторожу нужна помощь пользователя (агент висит посреди опасного действия, поднять не вышло, ошибка API); пунктирное кольцо над бледным зелёным — загрузка слуха; луна — тихий режим; бледное кольцо — Ома не запущена. Иконки — [Lucide](https://lucide.dev) (ISC).
- **Пузыри** у орба — до трёх, самый старый тает. По тону различаются: вы, Ома, агенты; кто говорит — приглушённым капсом над текстом. Пузыри агентов — пересказы Омы (итог хода, вопрос, важное промежуточное), а не сырой текст агента. Текст пузырей — без разметки markdown (звёздочек, маркеров списка, бэктиков), и у ответов Омы тоже; в чате окна разметка остаётся. Пока вы говорите, виден черновик «…», дальше — распознанный текст; кнопки «Отправить» нет. ЛКМ — окно с чатом пузыря (у агента — его чат, иначе — текущий чат Омы), ПКМ — убрать пузырь (черновик — отменить фразу, как Esc). Вне тихого режима гаснут через 10 секунд, в тихом — висят до ПКМ. Единственный агент в фокусе пузырей не даёт — на него и так смотрят; агентов несколько — пузыри есть.
- **Окно** (`Super+Shift+S`): слева первой строкой «Ома» — общий чат с Омой-помощником (с орбом и постоянной цветной подложкой, чтобы его было видно среди агентов), под ней агенты (работает / ждёт ответа / готово / простаивает; список обновляется на месте — прокрутка не сбрасывается, курсор клавиш остаётся на своём агенте), справа чат с Омой и поле ввода; чат держится у нижней границы. Пока окно открыто, разговор идёт в чате, пузырей нет. В шапке — счётчик ждущих агентов, микрофон (акцентный, пока идёт разговор), новый чат, история, звук (вкл/выкл — это «Сейчас тихо»), настройки; у края — тумблер «Ома вкл/выкл». Страница настроек — разделы в одном порядке: голос (голос, скорость), тихий режим, слух, орб, агенты; раздел без строк не показывается. Порядок задаёт `Model.SETTINGS_SECTIONS`, место строки для курсора — индекс её ключа в `SETTINGS_ROWS`, а `plugin/test.js` сверяет с ним страницу в `Window.qml`; под подписью строки может стоять вторая строка — почему так сейчас. Выключенная Ома — это остановленная служба: орба на столе нет, слух, модели и видеопамять свободны, хуки агентов молча ничего не делают; окно показывает «Ома выключена» и тумблер. Клик или Enter по агенту — его чат: лента агента и разговор с Омой о нём; Esc или строка «Ома» — назад в общий чат. Клик только показывает чат: её идущий ответ не обрывается, а мозг (процесс `claude`) переходит в этот чат, когда вы в нём напишете. Общий чат — текущий, если открыт не чат агента, иначе последний общий моложе двух часов, иначе новый (старые — в «Истории»). Разговор по клику на орб, микрофону в шапке или `Super+Ctrl+Alt+S` идёт в общий чат, даже если последним был чат агента, и окно переходит туда же — и после клика по агенту или чату из «Истории», который чат только показывает (микрофон включается сразу, прежний `claude` закрывается в фоне; новый ждёт его выхода, только если продолжает ту же сессию — в сессию пишет один процесс); ответ в окне ответа после вопроса агента по-прежнему уходит в чат агента. Окно идёт за любым начатым разговором (строка `chat` с `was` «*»), и за открытым окном ответа после новостей, «Ты тут?» и вопроса агента тоже: иначе окно, смотревшее другой чат, не показало бы ответ, который вы слышите. Окно ответа не открылось (тихий режим, микрофон занят) — мозг не переходит в чат спросившего агента. Реплики — пузыри: ваши справа, зелёные; Омы и агента слева. Текст пузырей выделяется мышью и копируется по Ctrl+C (новые строки ленты и чата выделение не сбрасывают); у пузырей Омы — кнопка «копировать» (ответ целиком). В буфер текст уходит без знаков ударения, которые Ома ставит для голоса (`wl-copy`). Лента агента — его последние 20 реплик из транскрипта Claude Code (ваши промпты, в том числе отправленные посреди хода, тексты агента и пересказ хода, который терминал показывает репликами); служебное — отчёты сабагентов, `<task-notification>`, тексты навыков, подписи картинок — не показывается. Посреди хода лента живая (хуки), в конце хода сверяется с транскриптом; последний ответ, который Claude Code ещё не дописал в файл, при сверке остаётся. Сообщения показываются целиком (до 8000 символов) и с разметкой Markdown: списки, заголовки, код, ссылки. Скриншоты, отправленные агенту, — миниатюрами в вашем пузыре; клик открывает картинку поверх окна Омы, клик или Esc закрывает; демон сохраняет их из транскрипта в `~/.cache/agent-speak/images`. Текст, набранный в окне, продолжает разговор — и из одного знака (порог в два знака против шума — только у слуха); вопрос остаётся в поле (бледным), пока Ома его не приняла: окно узнаёт это по `id` вопроса в её строке чата, а не по совпадению текста, а если она не запущена — не уходит, справа в поле «Ома не запущена», и Enter отправит его, когда она поднимется. Служба выключилась, пока открыта страница настроек или истории, — окно возвращается на главную с тумблером.
- **Название агента:** имя из `/rename`, иначе заголовок, который Claude Code сам даёт сессии (`ai-title` в транскрипте), иначе папка. Заголовок ищется в последнем 1 МиБ транскрипта один раз, дальше — только в дописанном; файл не рос — не читается.
- **Разговор** (клик по орбу, `Super+Ctrl+Alt+S`, микрофон в окне): Ома слушает; фразы копятся; договорили — реплика уходит сразу после паузы детектора речи (~0,7 с), оборвали на полуслове — Ома ждёт продолжения 2,5 с, не уверена — 1,3 с (конец реплики по звуку решает Smart Turn v3.2, `turn.py`, — только по фразе, вошедшей в черновик: эхо и непринятое он не судит; уверен — реплика уходит тут же, не дожидаясь тика; модели нет — всегда 1,3 с); после ответа слушает снова. Клик во время «слушаю» — конец разговора, клик во время «думаю» или «говорю» — перебить. Перебить можно и голосом. В наушниках на первом звуке фразы она встаёт на паузу, а решает распознанный текст: кашель, «угу», пустое — продолжает с начала прерванного предложения; слова — её ответ остаётся на паузе, а ваша реплика уходит мозгу. Мозг решил, что это было не ей («[молчу]»: «да, мам, сейчас»), — она продолжает прерванный ответ; ответил по делу (или вызвал инструмент) — прерванный ответ выбрасывается. Через динамики так же, только пауза ставится, когда фраза распознана. Это её пауза (`oma_pause` демона), не кнопка «пауза»: вашу паузу она не снимает, а свою снимает и в конце разговора. Через динамики её голос просачивается в микрофон и после эхоподавления, поэтому там она замолкает, только когда фраза распознана и это не её же слова; фраза почти из её слов — эхо, она выбрасывается; если вы заговорили, пока она договаривала, её последние слова в начале фразы срезаются, а ваши остаются (если фраза началась под её голос, хватает и одного её последнего слова: «Простаивает. Ок.» → «Ок.»). Эхо судится по началу фразы, даже если вы договорили позже: эхом может быть только речь, начатая, пока звучит её голос (и пока pw-cat доигрывает канал после её «смолкла» — до `played_at` из строки состояния службы, а не по своей константе; время начала слух берёт по звуку, а не по чтению). До того же `played_at` слух держит вход с эхоподавлением. Реплика, в которой нечего сказать вслух (только код или эмодзи), не оставляет её в «говорю»: служба сразу шлёт строку состояния с выросшим `voiced` — счётчиком отработанных реплик, и «говорю» кончается, когда `speaking` погас, а `voiced` не меньше числа её реплик (`voice`); конец звука — `played_at`. Пауза пользователя (кнопка «пауза», `agent-speak pause`) посреди её ответа возвращает фразу в очередь службы, `voiced` не растёт — «говорю» кончается по `user_paused` строки состояния: Ома слушает, и разговор кончается сам после 30 секунд тишины; сняли паузу — ответ доигрывает, пока она слушает. Ответ, сказанный, пока пауза стоит, ждёт её снятия в очереди, а Ома его звука не ждёт: служба засчитывает его сразу. Её собственная пауза при перебиве (`paused` без `user_paused`) «говорю» не кончает: ответила по делу — «говорю» держится до звука нового ответа. Начатое позже — ваше, даже из её слов: «Да, передай» сразу после её «…Скажи: да, передай» не теряется. Пока она думает, ваши слова через динамики обрывают ход так же, как в наушниках. Esc во время фразы отменяет её, Ома продолжает слушать. «Стоп», «хватит», «подожди» голосом — не вопрос мозгу: Ома обрывает всё, что звучит (свой ответ, чтение, новости), и слушает дальше. «Отбой» или «отмена» (в любой форме: «отмену», «отменить») — так же обрывает всё и заканчивает разговор: микрофон выключается. Отвечает коротко: на вопрос «да/нет» — «Да» или «Нет», на остальное — одной фразой до 15 слов (в промпте мозга — примеры таких ответов), без markdown. Голосом — коротко, текстом — сколько нужно: когда просят подробнее, мозг говорит главное одной фразой, ставит метку ‹подробно›, и детали после неё идут только в окно (в чате метки нет); ответ, вопрос к вам и кому что передано — всегда до метки, вслух. «Ок», «понял», «спасибо» после её ответа и тишина — разговор окончен: мозгу не уходит, микрофон выключается сразу, а не через 30 секунд; на её вопрос («Передать агенту?») «хорошо» — ответ. Кашель, вздох, междометия («кхм», «эм», «ну…») и пометки whisper в скобках («[кашель]») — не реплика. Пока она думает, начало звука ответ не обрывает: перебив решает распознанный текст, кашель ход не губит. Через динамики «угу», «ок» и кашель её не обрывают. Чужой разговор в комнате, телевизор, обрывок на полуслове мозг пропускает молча: отвечает меткой «[молчу]», она не звучит и не попадает в чат; на прощание («всё, свободна», «пока») — меткой «[конец]», и разговор закрывается. Инструмент молчания вместо меток не годится: модель звала его по кругу, 8 раз на одно «Кхм.». Отклик быстрее, пока мозг думает: реплика ушла — сразу короткий щелчок «услышала» (90 мс, туда же, куда её голос, в тихом режиме — нет); мозг взялся за инструмент — она говорит, что делает («Смотрю агентов.», «Читаю переписку агента.», «Готовлю поручение.», «Готовлю запуск.» — не «передаю»: голосом поручение ещё ждёт «да, передай», «Ищу в сети.»), и это же видно в окне; задумалась, ничего ещё не сказав, — «Секунду, подумаю.». Слово не звучит, только если она уже говорит. К каждой реплике мозгу едет свежий снимок агентов (в конце, между ‹агенты› и ‹/агенты›; в чате и названиях чатов его нет): на «как дела у агентов» она отвечает без круга на инструмент `agents` (2–4 с). Снимок — из ответа службы на `turn`: перед каждым ходом мозга (голосом, набранным, в тихом режиме) служба заново спрашивает окно в фокусе, пока поднимается `claude`; служба не ответила за секунду — снимок из подписки. За снимком — строка о её звуке: «Твой голос: выключен (тихий режим)…» или «включён, звучит в динамиках / в наушниках» (куда — по `out` из строки состояния службы, и при закрытом слухе): на «где звук?» она отвечает по факту, а не выдумывает. Клик по орбу и окно ответа на вопрос агента сразу поднимают процесс `claude`, пока вы говорите: первая реплика не ждёт его запуска (0,7–2 с). Мозг — в своей очереди: реплики, перебивы и переходы между чатами идут к нему по порядку, но Ома их не ждёт — Esc, клик по орбу и «стоп» работают, пока `claude` поднимается или поручение доставляется; перебив уходит после реплики и обрывает её ход. Итоги очереди (доставка поручения, вопрос подтверждения, сбой) несут номер своего хода: опоздавший итог прошлой реплики новый ход не закрывает, а сбой любой задачи очереди — ошибка с уведомлением, разговор не остаётся в «думаю». Длинное первое предложение ответа начинает звучать с первой запятой после 25 знаков. Разговор кончается сам после 30 секунд тишины, при блокировке экрана и сне. Пока идёт диктовка voxtype или созвон (микрофон захвачен другой программой), Ома не слушает.
- **Тихий режим:** ничего не звучит, только текст. По расписанию (по умолчанию 23:00–08:00) и вручную; ручное переключение действует до ближайшей границы расписания.
- **Что видит Ома:** сводку и ленты агентов, конец переписки любого агента (по умолчанию — в фокусе), выделенный мышью текст, поиск в интернете. Снимков экрана нет. Файлы мозг только читает и только в `~/Projects`: чтение и поиск вне этой папки (и своей `~/.local/share/agent-speak/oma`) Claude Code отклоняет (`permissions.blockReadsOutsideWorkingDirectories`), а что спросило бы разрешения — отказ (`dontAsk`); 2026-10-30 его Grep по всему `~` дал пик памяти 44 ГБ. Агентам он передаёт ответы и задания и запускает новых (раздел «Задания и ответы агентам»); прерывает и перезапускает их сторож (раздел «Сторож»). Всё это — только в терминалах herdr и Orca.
- **Мозг** — сессия Claude Agent SDK на чат (`~/.local/share/agent-speak/oma`), модель Sonnet, ответ — «Да» или «Нет» либо одна фраза до 15 слов; подробности — после метки ‹подробно›, только в окне. Чат агента привязан к его сессии; общий чат после двух часов тишины начинается заново.
- **Слух** — whisper large-v3-turbo на видеокарте. От сети модель загружена всегда (клик → «слушаю» мгновенно), от батареи — по первому клику и выгружается после 5 минут тишины. Вход — сырой микрофон ноутбука, как у диктовки voxtype: шумодав `mic_denoise` (RNNoise) под шум вентиляторов вырезает слова, эхоподавление `mic_aec` (webrtc) их портит — whisper слышал «Играет музыка» вместо речи; замеры — [docs/recognition.md](docs/recognition.md). Когда Ома говорит в динамики, слух на время её речи берёт `mic_aec`: там её голос вырезан, и перебив слышно; смолкла — снова сырой микрофон. Сырой микрофон включается не сразу по её «смолкла», а через секунду: pw-cat доигрывает ещё ~0,7 с. Остаток её голоса, если он прорвался, она узнаёт по тексту — фраза из её же слов отбрасывается как эхо, её слова в начале фразы срезаются. Гарнитура в ушах — её микрофон. Выключение слуха не зависает, даже если поток микрофона никто не читает: `pw-record` убивается и его stdout дочитывается (`reap` в `ear.py`); раньше `stop` мог висеть навсегда и клик по орбу не выключал слух. «Играет музыка», «[музыка]» и титры, которые whisper «слышит» в шуме, считаются тишиной. Процесс Омы запускается с `OPENBLAS_NUM_THREADS=1`: иначе потоки OpenBLAS после каждого расчёта признаков whisper крутятся вхолостую — 0,9–1,5 с процессора на вызов.

## Как звучат агенты

- **Ома пересказывает.** Дословно агенты не звучат. Конец хода и вопрос агента уходят лёгкой модели (Haiku), текст работающего агента за минуту — только при включённом «Пересказывать промежуточное» (`progress_digest`; выключено — в строке окна последняя фраза агента дословно, без пузырей и речи); она отвечает одной-двумя фразами по-русски, без имён файлов, функций и команд: что сделано, что требует внимания, что дальше. Пересказ попадает в пузырь агента и в строку «что сейчас» в окне. Промежуточное в пузырь и в речь — только важное (проблема, смена плана, неожиданный результат); неважное меняет лишь строку в окне. Модель не ответила или ответила не по форме — для итога звучит «готово», для вопроса — перевод уведомления Claude Code; промежуточное без модели молчит.
- **Что звучит.** При включённом «Следить за агентами» (`agents_voice`, страница настроек, по умолчанию включено) — вопросы, итоги и важное промежуточное, если не тихо. Выключено — Ома только голосовой помощник: об агентах ни пузырей, ни речи, модель не вызывается, орб не краснеет от ждущих; список агентов в окне остаётся. Каждая новость начинается с названия проекта: «agent-speak: фича готова, тесты прошли».
- **Приоритет.** Новости ждут, пока нет разговора с Омой и окна ответа (микрофон открыт — Ома услышала бы себя) и ничего другого не звучит, и уходят одной фразой: сначала вопрос, потом итоги, промежуточное — когда сказать больше нечего. Вопросы — по одному, старший первым, с «После этого ещё N вопросов». После озвученного вопроса итоги ждут ответа до 2 минут; ответ в терминале (промпт, разрешение или конец хода) снимает ожидание, а ещё не озвученный вопрос этого агента уже не звучит. Новый вопрос агента заменяет прежний; закрытый агент вопросов не держит.
- **Окно ответа.** Когда новости доиграли (вместе с хвостом звука — чтобы не слышать себя; конец звука служба берёт из того же `played_at`, что получает Ома), Ома 5 секунд слушает: ответ голосом уходит ей — одна реплика, после её ответа микрофон закрыт (после вопроса — в чате спросившего агента), тишина — окно закрывается; титры, которые whisper «слышит» в тишине («Субтитры создавал…»), разговор не открывают. Слух загружается заранее, пока новость звучит. Окно не открывается в тихом режиме, на заблокированном экране, при занятом микрофоне и во время разговора.
- **Тишина.** В тихом режиме пересказы — только в пузырях; новости тишины не копятся и после неё не звучат.
- **Ручное чтение** (`agent-speak read`) — ход окна в фокусе целиком, дословно, звучит и в тихом режиме.
- **Уведомления Claude Code** переводятся на русский — это запасная фраза вопроса: «Клоду нужно разрешение на команду», «Клод задал вопрос». Что именно ждёт Claude, берётся из последнего вызова инструмента в транскрипте. Незнакомые тексты и инструменты остаются как есть — пора добавить перевод в `notification_text` (`src/daemon.rs`). «Клод ждёт ответа» (простой после хода) не звучит.

## Слушает ли пользователь

Ома не говорит новости «в пустоту». Она держит одно из четырёх состояний:

- **слушает** — вы рядом, внимание свободно: новости звучат как обычно;
- **занят** — звонок (микрофон занят другой программой), открытая камера, видео или ваше «не сейчас»: речи нет, только пузыри, новости копятся;
- **нет на месте** — заблокированный экран или долгий простой клавиатуры и мыши (10 минут): молчит, копит;
- **вернулся** — первое движение после отсутствия.

Только видео делает вас «занятым» (играющий плеер с запретом на сон экрана); музыка — нет, под неё Ома говорит. Новость агента не звучит, если вы им заняты: открыт его чат в окне Омы или его вкладка в фокусе и вы печатаете (ввод за последние 30 секунд) или ждёте его ответа (ваш промпт ему — не раньше 2 минут назад). Просто вкладка в фокусе — не повод молчать: может, вы отошли или смотрите в телефон. Датчик простоя не отличает клавиатуру от мыши — «печатаете» значит любой ввод. В Orca все агенты — в одном окне, поэтому открытую вкладку Ома читает из базы Orca (`profile-state.db`, `activeTabIdByWorktree`; Orca пишет её за секунду после переключения) и сверяет с `ORCA_TAB_ID` агента; в herdr — какая панель в фокусе. База Orca и список панелей herdr спрашиваются один раз на всех агентов окна, а не на каждого; Orca и herdr (herdr внутри Orca) — параллельно. Начатую фразу Ома дочитывает, даже если вы перешли на вкладку её агента. Фокус Ома спрашивает только когда он нужен — перед новостью (и только если без учёта фокуса есть что сказать: итоги, ждущие ответа на озвученный вопрос, его не спрашивают), при ручном чтении и в начале каждого хода мозга, голосом и набранного, и в тихом режиме тоже (`turn`: служба отвечает строкой агентов с этим фокусом — её снимок «в фокусе» свежий), а не опросом раз в 2 секунды. Пустой стол (`hyprctl activewindow -j` отвечает `{}`) — не ошибка и в журнал не пишется.

- **«Ты тут?»** Простой больше минуты, а сказать есть что: Ома коротко спрашивает «Эй, ты тут? Есть новости.» и слушает 20 секунд с начала вопроса — с мига, когда пошёл его звук (первый кусок записан в pw-cat), а не когда он встал в очередь: синтез бывает долгим (холодный старт, перезапуск сервера синтеза), и тогда ни окно Омы (команду `listen` служба шлёт в этот миг), ни решение «нет на месте» не кончаются раньше, чем вопрос прозвучал, — одним окном, и в наушники, и в динамики (пока она говорит в динамики, слух берёт вход с эхоподавлением, а её собственное «…ты тут?» из динамиков ответом не считается: фраза уходит Оме как `said`, и эхо Ома узнаёт по ней, а не по своему прошлому ответу). Окно длится столько, сколько сказала служба (`secs`): эхо её вопроса и непринятая речь в комнате его не сокращают до 5 с. Раньше через динамики микрофон открывался только после фразы и хвоста, через 3–4 с, и слушал 5 с, а «нет на месте» решалось через 20 с — ответ на 8–10 секунде попадал в закрытый микрофон. Вопрос, ушедший без звука, ответа не ждёт; иначе новости молчали бы, а наушники оставались бы в режиме гарнитуры до возвращения пользователя. Из очереди его выбрасывает сама служба (стоп, тихий режим; тишина, выбросившая хоть часть вопроса, снимает его целиком — дозвучавший остаток микрофон не открывает), а у потока воспроизведения (синтез не смог его текст, запись в pw-cat не прошла и со второго раза, стоп или перебив до первого куска) — поток, и он шлёт об этом сигнал «фраза ушла без звука» в тот же канал, что «заговорила», «пошёл звук» и «смолкла». Служба судит по порядку сигналов, а не по тому, что видит в очереди, когда до них дошла: цикл, занятый дольше, чем вопрос синтезируется и пишется, видит «заговорила», когда поток уже смолк, но следом в канале — «пошёл звук», и окно ответа открывается. Вопрос в очереди — два предложения, и служба считает, сколько их ещё не прозвучало и не выброшено (сигналы потока, стоп, тишина); ответа она не ждёт, только когда ушёл весь вопрос: первое предложение выброшено, а второе прозвучит — окно ответа откроет его звук. Голос или движение мыши — новости; «не сейчас» — занят; тишина — нет на месте. Голосом засчитывается только похожее на ответ ей («да», «тут», «слушаю», «рассказывай», «через минуту», «Ома»…): другая речь в комнате — ребёнок, гости — ответом не считается, Ома слушает дальше. Сказать нечего — не спрашивает.
- **Возвращение.** После отсутствия от 3 минут Ома здоровается и вводит в курс: «С возвращением. Пока тебя не было: два проекта закончили, один ждёт ответа», затем сначала вопросы, потом итоги (больше трёх итогов Haiku сжимает в две-три фразы). Что она сказала, а вы, похоже, не услышали, повторится в сводке; если вы были рядом, повтора нет. Короткая отлучка — без приветствия.
- **«Ок».** Короткий ответ после новости («ок», «понял», «спасибо») сразу закрывает микрофон; после вопроса агента реплика уходит агенту как обычно, а микрофон закрывается, как только Ома договорит. Окно, которое Ома открыла сама (после «Эй, ты тут?», новостей, вопроса агента), — одна ваша реплика и её ответ: потом микрофон закрыт, дальше речь в комнате не слушается и в Claude не уходит; продолжить разговор — кликом по орбу.
- **Своими словами.** «Не сейчас», «давай потом», «замолчи» — занят на 15 минут; «я отойду» — нет на месте; «рассказывай», «я вернулся», «что нового» — слушает. Фразы понимает мозг Омы, любые по смыслу; работает и в разговоре по клику.
- **Тихий режим.** Накопленное, пока вас не было, начало тишины не стирает: оно звучит сводкой при первом вводе после её конца.
- **Наушники.** Датчик FreeBuds читает «в ушах» и у наушника, лёгшего на стол датчиком вниз, поэтому одному «в ушах» Ома не верит. Через минуту без ввода она спрашивает «Эй, ты тут?» туда, куда идёт звук. Если это Bluetooth-наушники (датчик говорит «в ушах» или молчит) и ответа нет 20 секунд — спрашивает ещё раз в динамики ноутбука и слушает его микрофоном с эхоподавлением. Нет ответа и там — вас нет на месте, выход возвращается в наушники. Вставили наушники (было «вынуты», стало «в ушах») — это как движение мыши. Вынули и положили датчиком вверх — Ома не уверена и говорит и слушает через ноутбук, даже если наушники в режиме гарнитуры. Если вы ушли в наушниках, ответ услышит только их микрофон, а он работает лишь в режиме гарнитуры. Поэтому перед «Эй, ты тут?» в Bluetooth-наушники в режиме музыки Ома включает гарнитуру тем же путём, что селектор HEADPHONES MODE (`omarchy-bt-mode` из dotfiles), спрашивает и слушает микрофон наушников — сразу, с начала фразы, чтобы «да», сказанное, пока она договаривает, не потерялось, — а когда вопрос решён и разговор кончился — возвращает музыку. Гарнитуру, включённую вами, она не трогает. Нет скрипта — спрашивает в режиме музыки и слушает ноутбук. Датчик «в ушах» (у автора FreeBuds Pro 4) читает [OpenFreebuds](https://github.com/melianmiko/OpenFreebuds), он необязателен: нет датчика — наушники ничего не решают. Датчика положения у OpenFreebuds нет.
- **Факты — от оболочки.** Простой, блокировку, звонок, видео и наушники пишет сервис оболочки `predmaxim.presence` (снимок `$XDG_RUNTIME_DIR/predmaxim-presence.json`); решает Ома. Мониторы уровня самой оболочки (открытая панель звука, орб, что слышит голос) звонком не считаются — по стоковому правилу `AudioNodes.isShellLevelMeter`. Факт `screencast` (экран показывают: поток показа портала, узел `Video/Source` без `device.id`) служба уже читает (`Facts.screencast`, в старом снимке поля нет — не показывают), но пока ничего по нему не делает: тишину при показе строит следующая волна. Нет сервиса или снимок старше 90 секунд — Ома ведёт себя как раньше: говорит новости, когда они есть. В журнал службы снимок попадает, только когда меняются сами факты (ввод есть или нет, блокировка, микрофон, камера, видео, наушники), а не на каждый сдвиг момента простоя.
- **Фоновые помощники.** Конец хода агента, у которого ещё работают собственные фоновые помощники, итогом не звучит; итог — когда закончит последний. Ход, который начали не вы, а отчёт помощника (так работает агент-оркестратор: «ревьювер принял ответ», «исполнитель закрывает находку»), — его переписка с помощниками: Ома пересказывает его в окне, а вслух говорит, только если модель сочла важным — вся работа готова или агент прямо обращается к вам. Напишете ему посреди такого хода — итог снова ваш.

## Сторож

Цель — чтобы работа агентов не стояла. Раз в минуту (`watch_every`) Ома проверяет каждого агента. Если что-то починила сама, говорит об этом коротко. Если нужен пользователь, звучит срочное: оно слышно и когда пользователь «занят», но не в тишине и не когда его «нет на месте». Несколько новостей склеиваются в одну фразу; первым звучит срочное, затем восстановленное, вопросы и итоги. «Всё в порядке» Ома говорит только на вопрос. Здоровье агента видно в окне, под его строкой: «завис», «лимит до 15:20», «нет связи».

- **Завис.** Агент «работает», а 12 минут (`hung_after`) нет ни записей в транскрипте, ни в транскриптах его сабагентов и агентов его Workflow, ни хуков. Что ход идёт, Ома берёт из транскрипта, а не из файла сессии: тот бывает «busy» часами. Читается хвост транскрипта, 256 КиБ; если в нём нет ни одной целой записи хода (одна строка результата инструмента или `api-request-blob` бывает больше), окно растёт вдвое, до 16 МиБ. Ход кончен (конец хода, Esc пользователя, ошибка API) — агент ждёт, а не висит. Агент с вопросом к пользователю (вопрос с вариантами, одобрение плана) тоже не висит, даже если уведомление потерялось. Действия идут по ступеням:
  1. Висит сабагент: Ома жмёт Esc и пишет агенту «Сабагент висел N мин, я прервала ход. Перезапусти его, если он ещё нужен».
  2. Висит вызов или поток ответа: лёгкая модель смотрит на вызов и экран терминала. Висит — Esc и «Ход завис…, продолжай с того места, где остановился». Работа долгая по природе (сборка, тесты, ожидание) — Ома ждёт ещё. Тишина от трёх порогов — Esc без модели.
  3. Не помогло за полпорога — Ctrl+C дважды, и агент перезапускается, как после падения.
  4. Больше трёх попыток за час — срочное «поднять не получилось, посмотри сам. Через N мин попробую снова». Ома не сдаётся насовсем: как только старая попытка выйдет из часа, она пробует снова, без пользователя.
- **Не трогает опасное.** Вызов с push, удалением, `git reset`, force, миграцией, деплоем или записью в базу Ома не прерывает: срочно говорит «агент завис посреди push — не трогаю, посмотри сам». Непонятный инструмент MCP или незнакомый вызов — так же. Висит сабагент — смотрится его вызов (по метафайлу сабагента): «сабагент завис посреди миграции — не трогаю».
- **Упал.** Процесс агента исчез посреди хода. Если пользователь минуту не трогал ввод, а терминал вернулся к приглашению оболочки, Ома набирает там `claude --resume <id>` с флагами пользователя и словами «Ты закрылся посреди хода, я перезапустила». Флаги — белый список: права, модель, усилие, каталоги. Падение не путается с выходом. Агент, вышедший сам, присылает хук `SessionEnd`: это закрыл пользователь, и Ома молчит. Пропала сессия, а процесс жив (`/clear`, `/resume`) — тоже не падение. Если пользователь был за компьютером, он, скорее всего, закрыл агента сам — Ома только сообщает.
- **Лимит.** Строка статуса Claude Code даёт проценты окон «5ч» и «неделя», rollout Codex — свои. Ома считает темп за 15 минут. Если окно заполнено на 95 % и больше (`limit_threshold`) и лимит кончится раньше сброса, агенты и их сабагенты получают факты через хук `PostToolUse`, по разу: «лимит 5ч — 96 %, кончится через ~12 мин, сброс через 40 мин». Текст подсказки обновляется раз в минуту, поэтому сабагент, прочитавший её позже главного агента, видит верные минуты. Решает агент: успевает — доделывает, не успевает — записывает в доку, что сделано, и останавливается со строкой «Остановился по лимиту». Жёстко Ома не прерывает никого. Пока прогноз плохой, промежуточное не пересказывается — это и её расход лимита. Агент встал, темп упал, и прогноз стал хорошим, а окно всё ещё у порога — эпизод держится ещё 10 минут, и подсказки после паузы не рассылаются заново. Лимит кончился — одна фраза на все агенты: «Кончился лимит Claude, сброс в 15:20». Через минуту после сброса Ома будит вставших: «Лимит сброшен, продолжай по своей записи в доке».
- **Связь.** Ход кончился ошибкой «Connection lost» — через минуту Ома просит агента продолжить, не больше трёх раз за полчаса, дальше — срочное «связь не держится».
- **Ошибки API.** Нужен вход, запрос отклонён фильтрами, неизвестная ошибка — срочное, один раз.
- **Помощники молчат.** Ход кончен, фоновые помощники агента работают, и все молчат 12 минут. Помощника видно по его метафайлу (`subagents/*.meta.json` без `finished`, с запуска процесса агента). Workflow — тоже помощник: пока запуск в хвосте транскрипта — по его `taskId` до отчёта `<task-notification>`, позже — по папке `subagents/workflows/<run>` без итога `workflows/<run>.json`; пока он идёт, конец хода родителя — не «готово», а «работает». Помощник бывает сервером и молчит часами, поэтому Ома сначала спрашивает модель. Только если та ответит «висит», Ома пишет агенту: «Твой фоновый помощник молчит… проверь его». Обычно эта просьба будит агента, и проверка начинается заново. Если агент не отозвался за 12 минут, Ома срочно зовёт пользователя. Других агентов это не касается.
- **Ждущий вопрос не повторяется.** Вопрос агента звучит один раз. Дальше он виден на орбе (счётчик ждущих) и в окне, голосом Ома о нём не напоминает.
- **Где действует.** Писать агенту, прерывать и перезапускать Ома может, только если терминал агента в herdr или Orca. Терминал находится по окружению процесса агента: herdr — `HERDR_PANE_ID` и `HERDR_SOCKET_PATH`, Orca — `ORCA_TERMINAL_HANDLE`. Окружение наследует всё, что запущено из такого терминала, поэтому терминал засчитывается, только если им владеет сам мультиплексор: первый предок агента, не считая оболочек, — сервер herdr или pty-хост Orca. Окно foot, открытое из терминала Orca, — не терминал Orca. herdr, запущенный в терминале Orca, — панель herdr, а Orca, запущенная в панели herdr, — терминал Orca. Агент вне них (обычное окно терминала) получает только подсказки про лимит; о зависшем Ома говорит «он не в herdr или Orca — перезапусти сам», тоже после вопроса модели. Перед набором текста Ома стирает строку ввода (Ctrl+U), чтобы недонабранное пользователем не ушло вместе с её текстом; вернуть стёртое — Ctrl+Y.

## Задания и ответы агентам

- **Скажите коротко.** «Пусть агент почты узнает, какие проблемы есть у приложения». Ома разворачивает это в полное задание: что сделать, где искать, что вернуть. Отправляет сразу, без «точно отправить?». Вам она говорит смысл и кому, не текст задания: «Передала проекту omarchy-mail: попросила найти проблемы на всех ресурсах приложения». Полный текст виден в ленте агента в окне.
- **Ответ на вопрос агента.** После озвученного вопроса Ома 5 секунд слушает в чате спросившего агента, и ваша реплика обычно и есть ответ ему. Ома передаёт ответ полностью, с нужными деталями. Ответить можно и позже, голосом или текстом, назвав проект. Вопрос к самой Оме («а что он имеет в виду?») агенту не уходит. Под имя подходят два агента — Ома спросит, какому.
- **Меню вариантов и одобрение плана** Claude Code Ома проходит клавишами. Вариант — его цифрой. Свой ответ — через «Type something». На несколько вопросов сразу или выбор нескольких Ома отвечает обычной репликой: меню отклоняется («Chat about this»), ответ приходит следом. План — пункт его цифрой: «1» (одобрить) — и без метки, если на экране он «Yes…»; любой другой (например, «Yes, manually approve edits») — только с меткой, которую Ома прочла с экрана и назвала; или «Tell Claude what to change» с вашими правками: цифра, текст правок, Enter — и при ответе текстом, и при выборе этого пункта по метке; без текста — отказ «пустой ответ», а не пустое поле у агента. Номер этого пункта Ома берёт с экрана. Цифру Ома жмёт, только сверив экран: у пункта та же метка, что у варианта в вызове агента (и та, которую назвала она сама, если назвала); на экране другое меню — устаревший или повторный ответ, разрешение вместо вопроса — «меню сменилось, не жму». Одобрение плана пункт 1 на экране сейчас — «Yes, and use auto mode», то есть включает и auto mode: `tell` возвращает метку нажатого пункта, чтобы Ома её назвала. Заранее, до вопроса подтверждения, пункты меню агента читает `agent-speak menu <session>` — только экран, ничего не нажимается: Ома называет в вопросе тот пункт, что увидите вы, а его метку передаёт в `tell` для сверки. Вопрос звучит так: «Одобрить план проекта agent-speak — пункт «Yes, and use auto mode»? Скажи: да, передай.»; пункт не «Yes…» одобрением не называется: «Выбрать пункт плана проекта agent-speak «Tell Claude what to change»: назвать файл b.txt? Скажи: да, передай.» — а текст правок, который уйдёт, Ома показывает в окне; меню на экране нет — не спрашивает, а говорит, что не вышло. Метку варианта в вопросе с вариантами Ома берёт из снимка агентов (без описания после « — ») и тоже передаёт в `tell`; набранное в окне сверяется так же. После нажатия она говорит, какой пункт нажат: «…Нажала «Yes, and use auto mode».»
- **Голосом агентам ничего не уходит без подтверждения.** Любое задание, ответ агенту или вариант меню, сказанные голосом, код держит, пока следующая ваша реплика не будет «да, передай» (для запуска — «да, запускай»; 2–4 слова, без «не»), не позже чем через минуту. Перед этим Ома говорит, кому и что: «Передать проекту agent-speak: делать обе оптимизации? Скажи: да, передай», а полный текст, который уйдёт, показывает в окне и в чате вместе с вопросом: вопрос не прозвучал — нет и текста. Ждать «да, передай» поручение начинает, только когда вопрос прозвучал в том же ходе: если ход, в котором мозг вызвал `tell` или `launch`, уже сменился (перебили, новая реплика), вопрос не звучит и поручение не ждёт — подтвердить неуслышанный вопрос нельзя. Поручение хода, который сменился, пока `tell` читал экран агента (одобрение плана), не уходит вовсе, и набранное тоже; запрет «в этом ходе больше ничего» на новый ход не переносится. Этот вопрос строит и говорит код, как только мозг вызвал `tell` или `launch`, — не второй проход модели, который его лишь повторял (по 14 таким ходам — на 1,0–5,2 с позже, медиана 1,6 с); на вопросе ход мозга кончается: после `tell` или `launch`, которые спросили подтверждение, штатный хук `PostToolUse` Agent SDK отвечает `continue: false`, и второго запроса к модели нет (раньше модель отвечала «[молчу]» — лишний запрос и флаг вокруг её ответа). Вопрос звучит последним, разговор ждёт ответа, а причину остановки (`stopReason`) модель видит в следующем ходе. «Да» или «передай» по отдельности — переспрашивает. «Нет», «отмена» — «Хорошо, не передаю». Любая другая реплика («продолжай», «давай», набранное в окне) снимает поручение, ничего не уходит, мозг об этом знает. Модели запрещено составлять задания из обрывков и перебивов: непонятно — переспросить. Так стало после 2026-10-29: в разговоре с перебивами Ома сама составила задание из обрывков («Стой. Сделай. Короче. Стоп.»), приняла «продолжай» за согласие, и текст набрался в строке ввода агента. Набранное в окне по-прежнему уходит сразу.
- **Опасное — только с подтверждением голосом.** Push, удаление, деплой, миграция, `git reset`, force, запись в базу. Ома не отправляет такое по ослышке и говорит: «Это пуш. Скажи: подтверждаю пуш». Задание уйдёт, только если следующая ваша фраза — «подтверждаю пуш» (или «удаление», «деплой», «миграцию», «сброс», «форс», «запись»), не позже чем через минуту. Совпадение проверяет код по распознанному тексту, не модель; слово с одной ошибкой распознавания засчитывается («подтверждаю душ» — это «пуш»), а «подтверждаю» с другим словом — Ома переспрашивает, ожидание держится. «Не подтверждаю пуш» — отказ: «Хорошо, не передаю». Другая фраза отменяет ожидание, а до неё в этом ходе Ома не передаёт ничего — даже перефразированное. Опасное ищется в вашей фразе, в тексте агенту и в вопросе агента, на который вы отвечаете: «да» на «Запушить?» тоже требует «подтверждаю пуш», а «нет» — обычного «да, передай». Ответ вариантом меню проверяется по самому варианту. Отказ не прикрывает опасное, дописанное к нему («нет, лучше удали ветку»). Набранное в окне подтверждения не требует — там ослышки нет.
- **Новый агент.** «Запусти агента в agent-speak, пусть обновит доки». Ома запускает Claude в проекте Orca, во вкладке-терминале, с флагами из настроек Orca — теми же, что у ваших агентов. Известные проекты — worktree Orca. Папку вне Orca Orca не запускает: «этого проекта нет в Orca — добавь его, и я запущу». Попросите herdr («запусти в herdr…») — Ома откроет новое рабочее пространство herdr в папке проекта и запустит там Claude с `--dangerously-skip-permissions` (как у агентов в Orca; своих настроек агента у herdr нет). Проекты herdr — git-репозитории в `~/Projects` (до трёх уровней, например `~/Projects/omarchy/own/agent-speak`). Orca или herdr закрыты — Ома говорит «Orca не запущена» или «herdr не запущен — открой его, и я запущу»; сама их не открывает.
- **Где действует.** Только у агентов в терминалах herdr и Orca, как у сторожа. Агенту вне них Ома не передаст и скажет об этом. Меню разрешения (агент без обхода прав просит разрешить команду) Ома не трогает: «агент ждёт разрешения в терминале — ответь там». Терминал не ответил за полторы минуты — Ома говорит «не знаю, дошло ли»: повтор мог бы дать второй пуш или второго агента.

## Управление

| Что | Как |
|---|---|
| Ома вкл / выкл | тумблер в шапке окна, «Ома» в меню приложений, ПКМ по значку в центральной группе (когда выключена: значок сам запускает `agent-speak on` для своей связи, а орб — через `omarchy-shell predmaxim.oma start`; юнит `Type=notify`, `agent-speak on` возвращается, когда сокет службы уже есть, поэтому и орб, и подсказка значка подключаются сразу, а не через 5 с), `agent-speak on` / `off` (выключенная не стартует и после входа) |
| Звук вкл / выкл | кнопка в шапке окна, ПКМ по значку в центральной группе, «Сейчас тихо» в настройках |
| Окно Омы | `omarchy-shell predmaxim.oma toggle` (Super+Shift+S), ПКМ по орбу, ЛКМ по значку в центральной группе; `… show` — только открыть |
| Начать / закончить разговор | клик по орбу, микрофон в шапке окна, `agent-speak voice` (Super+Ctrl+Alt+S), `omarchy-shell predmaxim.oma talk` (служба выключена — открывает окно Омы с тумблером) |
| Отменить фразу | `Esc` во время фразы, `omarchy-shell predmaxim.oma cancel` |
| Следить за агентами | тумблер на странице настроек окна, `agents_voice`; выключение обрывает и то, что звучит сейчас |
| Пересказывать промежуточное | тумблер на странице настроек окна, `progress_digest` |
| Прочитать ход окна в фокусе / остановить | `agent-speak read` (Super+Shift+Alt+S) |
| Пауза / продолжить | `agent-speak pause` (Super+Ctrl+Shift+Alt+S) |
| Стоп | `agent-speak stop` (диктовка voxtype тоже останавливает — у автора `Alt+Space`) |

Хоткеи задаются в Hyprland (у автора — `omarchy-dotfiles`, `hyprland.lua`). Esc плагин ловит сам: временный бинд Hyprland включается только пока идёт фраза и 1 секунду после отмены, в остальное время Esc достаётся программе под окном.

Уведомления — только о том, чего не видно на орбе: «Нечего читать», «В фокусе нет агента», «Синтез упал», ошибки Омы (одинаковый текст — не чаще раза в 5 минут).

## Настройки

`~/.config/agent-speak/config.toml` (сервис перечитывает файл сам; удобнее — страница настроек в окне Омы). Значения из файла проверяются так же, как из окна: неверное (например, `hung_after = 0`) заменяется умолчанием ключа, причина — в журнале. Файл, который не читается как TOML (опечатка, недописанная правка), не применяется — остаются прежние настройки, — и служба его не перезаписывает, пока его не исправят:

| Ключ | Значения | По умолчанию |
|---|---|---|
| `agents_voice` | `true` / `false` — следить за агентами: пересказы, пузыри и голос о них; выкл — Ома только помощник | `true` |
| `progress_digest` | `true` / `false` — пересказывать промежуточное моделью раз в минуту на агента; это три четверти вызовов Haiku | `false` |
| `speaker` | `kseniya`, `xenia`, `baya`, `aidar`, `eugene` | `kseniya` (термины читает хуже xenia; голос, уже записанный в файле, новое умолчание не меняет — сменить в настройках или `agent-speak set speaker kseniya`; образец голоса в настройках кончается вопросом — слышно, как модель его поднимает) |
| `rate` | `x-slow` … `x-fast` | `medium` |
| `quiet_schedule` | `true` / `false` | `true` |
| `quiet_from`, `quiet_to` | `ЧЧ:ММ` | `23:00`, `08:00` |
| `quiet_override` | `""` / `on` / `off` (до границы расписания) | `""` |
| `orb_pos` | `угол,dx,dy` — угол `top-left`, `top-right`, `bottom-left`, `bottom-right` и отступ в пикселях (орб тащится мышью) | `bottom-right,0,0` |
| `orb_over_fullscreen` | `true` / `false` — орб и пузыри и над полноэкранными окнами (слой Overlay), иначе под ними (Top); меняется на лету | `true` |
| `watch_every` | секунды между проверками сторожа, 15–3600 | `60` |
| `hung_after` | минуты без событий у работающего агента — «завис», 2–240 | `12` |
| `limit_threshold` | процент окна лимита, с которого Ома считает прогноз, 50–100 | `95` |

Словарь произношений — `~/.local/share/agent-speak/terms.tsv` (`слово<TAB>произношение`, `+` — ударение). Незнакомые слова сначала читаются транслитерацией, а фоновая самая лёгкая модель агента дописывает их в словарь. Произношение — одно слово из русских букв, дефиса и `+` перед ударной гласной: строку с пробелами, скобками или чужими буквами словарь при загрузке пропускает (слово спросится заново), `+` не перед гласной убирает. Дефисы читаются по буквам, только если частей столько же, сколько букв (`npm` — `эн-пи-эм`); слоги `+ан-тро-пик` звучат слитно.

## Устройство

- `agent-speakd` — сервис на Rust (`systemctl --user status agent-speakd`; журнал `journalctl --user -u agent-speakd`). Держит реестр агентов (`~/.claude/sessions/*.json` — только сессии, запущенные пользователем, `entrypoint: cli`; процессы `codex`; хуки), решает, что звучит, и держит запущенным процесс Омы (`python -m agent_voice`, перезапуск с растущей паузой 10 с → 5 мин). Команды Оме пишутся в её stdin без ожидания (`O_NONBLOCK`): труба полна — Ома команды не читает, и она считается упавшей, а цикл службы не встаёт. Такой, зависшей, Оме служба шлёт SIGABRT, а не SIGKILL: дамп уходит в systemd-coredump (`coredumpctl`), а трасса всех её потоков Python — в журнал (служба запускает её с `PYTHONFAULTHANDLER=1`); процесс пожинается в стороне, цикл службы дамп не ждёт; не вышла за 30 с (SIGABRT пойман, дамп завис) — SIGKILL; ждать её нечем (`pidfd_open` или `poll` не удались) — SIGKILL сразу, с настоящей ошибкой в журнале: ждать без срока значило бы не поднять новую Ому. Запись в трубу не прошла по другой причине (труба закрыта) — SIGKILL сразу. Новая Ома поднимается не раньше, чем прежняя пожата: двух Ом с одним микрофоном и GPU не бывает. Юнит — `Type=notify`: о готовности служба сообщает systemd (`READY=1` в `$NOTIFY_SOCKET`) сразу после того, как создан сокет, поэтому `agent-speak on` возвращается, когда к ней уже можно подключиться, и окно не ждёт повторной попытки. Оме служба передаёт путь к себе (`AGENT_SPEAK_BIN`, для `agent-speak tell | launch | projects`) таким, каким её запустили — ссылкой из `ExecStart`, а не `/proc/self/exe`: тот после `cargo build` у живой службы указывает на удалённый файл. Сборка release — с `panic = "abort"`: паника любого потока завершает службу, и systemd поднимает её заново (`Restart=on-failure`), а не оставляет немой.
- Источники агентов: Claude — хуки `MessageDisplay`, `Stop`, `UserPromptSubmit`, `Notification` и статус файла сессии; Codex — rollout-файл и `notify`. inotify следит только за `~/.codex/sessions`: за транскриптами Claude (`~/.claude/projects`, сотни папок) — нет, вживую их заменяют хуки.
- `src/digest.rs` — пересказ: `claude -p --model haiku` с теми же флагами, что у словаря (без сессий, настроек и инструментов), три воркера — пересказ запускает не больше трёх процессов `claude` разом; ответ — `{"say", "important"}`, не JSON — запасная фраза и строка «пересказ не удался» в журнале. В задании — хвост текста агента и последний промпт пользователя; у вопроса — последний текст агента и ввод его вызова (вопрос с вариантами, план, команда). Готовый пересказ звучит сразу, если сейчас можно говорить, а не со следующим тиком демона.
- `src/news.rs` — доска новостей: приоритет (срочное сторожа, восстановленное, вопросы, итоги, промежуточное), вопросы по одному с «ещё N», ожидание ответа.
- `src/watch.rs` — сторож: правила на фактах об агентах (активность, вызов в полёте, ошибка API, помощники, терминал) → действия и фразы. `src/limits.rs` — проценты лимитов, прогноз и файлы подсказок `$XDG_RUNTIME_DIR/agent-speak-hints/`. `src/mux/` — адаптеры терминалов: трейт `Mux`, `herdr.rs` и `orca.rs` (их CLI с таймаутом 10 с, в отдельном потоке действий; выход CLI ждётся через pidfd, без опроса — вызов стоит столько, сколько работает сам CLI); ядро знает только трейт — tmux или своё добавляется новой реализацией.
- `src/orders.rs` — передача агентам, CLI `agent-speak tell <session> <option> <text> [метка варианта]` (в stdout — метка нажатого пункта меню с экрана; `tell` идёт через службу — сокет, запрос с ответом — и исполняется в её потоке действий, в одной очереди с действиями сторожа, поэтому две записи в одну панель не перемешиваются, а экран сверяется прямо перед нажатием), `menu <session>` (пункты меню на экране агента построчно «n. метка», как их видит пользователь; только чтение, без службы; меню нет — ошибка), `launch <path> <text> [orca|herdr]`, `projects [orca|herdr]` (по умолчанию `orca`). Вызов в полёте по транскрипту решает, как передать: меню — клавишами, иначе — текстом одной строкой. Ошибка — строка в stderr, код 1; её дословно получает мозг. Запуск, список проектов и ответ «папки нет в списке» — методы трейта `Mux` (`launch`, `projects`, `no_project`), они есть у Orca и herdr. herdr: `workspace create` → `agent start <папка>-<workspace> --kind claude` (имя агента в herdr уникально) → `agent prompt`; сессия — из `HERDR_SOCKET_PATH`, иначе общая.
- `python/agent_voice/` — Ома: слух (`ear.py`), разговор (`conversation.py`), мозг (`brain.py`, инструменты `tell`, `projects`, `launch`; агента в `tell`, `agent_feed`, `agent_tail` ищет `pick_agent`: точный id, часть названия или проекта, часть id — несколько подходящих, и Ома переспрашивает, перечислив их), передача агентам (`orders.py`: голосом всё ждёт «да, передай», опасное — «подтверждаю …»), контекст (`context.py`). Команды получает строками в stdin от демона (в том числе `warm` — загрузить слух заранее и `listen` с `secs` — окно ответа после новостей: `{"do":"listen","secs":5,"kind":"news"|"question","said":…,"key"?}` после того, как новость отзвучала; на «Ты тут?» — `{"do":"listen","secs":20,"kind":"here","said":"Эй, ты тут? Есть новости.","speakers"?:true}` в миг, когда пошёл звук вопроса (первый кусок записан в pw-cat), а не при постановке в очередь, `secs` — всё окно от этого мига), события отправляет в его сокет.
- `python/silero_tts.py` — синтез Silero, модель держится в памяти; звук ограничен ±1 перед int16 (у `eugene` пики выше — без этого треск). Ответ — длина и PCM; длина `0xFFFFFFFF` — ошибка синтеза: фраза пропускается с записью в журнал, а не ждёт повтора (повтор не поможет); не отвечает сам сервер — фраза ждёт, сервер перезапускается. Текст, в котором после подготовки нечего сказать (только код или эмодзи), остаётся в пузыре, в журнале — «нечего сказать вслух».
- Сокет `$XDG_RUNTIME_DIR/agent-speak.sock`, JSON-строки. Клиенту: строка состояния (в ней `talking`, `agents_voice`, `progress_digest`, `orb_pos`, `orb_over_fullscreen`, `trouble` — агентов со срочной проблемой сторожа, `played_at` — когда кончается или кончился звук последней речи, CLOCK_MONOTONIC в секундах, те же часы, что `time.monotonic()` в Python; `speaking` гаснет раньше, когда записан последний кусок, а `played_at` — это конец канала pw-cat: его остаток (FIONREAD на пишущем конце) плюс задержка узла `--latency=100ms`. Задержку графа PipeWire и устройства (буфер ALSA, кодек Bluetooth) он не включает, и запаса в нём нет: в динамиках звук может кончиться позже. Система её надёжно не отдаёт: `pactl list sink-inputs` у играющего pw-cat показывает 0 мкс, а `pw-dump` даёт задержку портов в квантах без текущего кванта графа; `voiced` — сколько реплик (`voice`) нынешней Омы отработано: все их фразы записаны в pw-cat, оборваны (стоп, перебив, тихий режим) или звука не будет вовсе (только код или эмодзи, тихо) — такая реплика засчитывается сразу, и строка уходит сразу; счёт — с запуска этой Омы, реплики прежней не входят; Ома кончает «говорю», когда `speaking` погас и `voiced` не меньше числа её `voice` (не «равен»: лишняя засчитанная реплика оставила бы её в «говорю» навсегда) или очередь службы на паузе пользователя (`user_paused`: фраза вернулась в очередь, `voiced` не растёт; `paused` — пауза очереди вообще, и её при перебиве тоже), а `played_at` не трогается; реплика, пришедшая на паузу пользователя, засчитывается сразу — ждёт снятия паузы в очереди, но Ома её звука не ждёт — это конец звука последней настоящей речи; `out` — куда идёт голос: `speakers` — динамики ноутбука, `headphones` — выход по умолчанию Bluetooth; проводные наушники в гнезде ноутбука — пока `speakers`. Выходы служба не спрашивает на каждую строку: свой поток держит `pactl subscribe` и перечитывает выход по умолчанию и динамики только по событиям «change on server» (сменился выход по умолчанию) и «new/remove on sink» (выход появился или пропал); сменился `out` — строка состояния уходит сразу; подписка оборвалась — новая через секунду, а если pipewire-pulse не ответил на чтение выходов при прошлой — всё реже, до раза в 30 с, с одной строкой в журнале на серию отказов), строка `{"agents":[…]}` (у агента `health` — слово сторожа, `ask` — вопрос с вариантами, который ждёт ответа), за ней при подписке — `{"permissions":[…]}` и `{"later":[…]}` (карточки разрешений и отложенные поручения волны «Джарвис»; пока функций нет, списки пустые; плагин держит их в `link.permissions` и `link.later`), затем `bubble` (у пузыря агента — `agent`, id сессии; черновик `draft` с `hearing`, `me`), `chat`, `chat_delta`, `chats`, `ripple` (`{"ripple":{"tone":"final|question|status"}}` — волна на орбе: новость пришла, а Ома её сейчас не говорит; плагин отдаёт её сигналом `link.ripple`, служба её пока не шлёт). Сервису: `subscribe`, `set`, `say`, `read`, `stop`, `pause`, `tell` (ответ агенту; служба отвечает строкой `{"ok": метка}` или `{"err": …}`), `oma` (команда Оме: `talk`, `cancel`, `ask` — `text`, `key` и `id`: принятую набранную реплику Ома возвращает строкой `chat_delta` с `role` `me` и тем же `id`, `open`, `new`, `chats`, `listen` с `key`), от Омы — `voice`, `voice_state` (с `talking`), `hush`, `emit`, `chime` (только щелчок), `turn` (перед каждой репликой мозгу, и в тихом режиме: запрос с ответом — служба спрашивает фокус и отвечает строкой `{"agents":[…]}`, её же получают подписчики; запрос шлётся отдельным соединением, ответ читается. В подписанном соединении `tell` и `turn` не исполняются: служба отвечает `{"err": …}`, не трогая таймаут записи подписки. В постоянном соединении без подписки непрочитанный ответ ложится в буфер сокета, и соединение живёт дальше; когда ответы переполнят буфер, запись ждёт секунду, затем служба закрывает соединение вместе с командами в нём); хуки — `agent-speak hook <вид>`.
- Порядок полей строки состояния — протокол: новые поля дописываются только в конец, и `Model.OFFLINE` плагина повторяет их все в том же порядке (`plugin/test.js` сверяет его со `struct Status` службы). Поля волны «Джарвис» (дизайн `docs/superpowers/specs/2026-11-12-oma-jarvis-wave-design.md`) объявлены заранее, за `user_paused`, с нейтральными значениями «функции ещё нет»; строитель функции меняет только значения своих полей. По порядку: `quiet_why` (причина тишины: `""`, `dnd`, `screencast`), `dnd_quiet`, `hush_summary`, `screencast_privacy`; `orb_satellites`; `media_hold` (звук занят Омой — музыка на паузе), `music_pause`; `limit` (фраза «лимит почти кончился» или `""`), `limit_warn`; `ear_in` (вход Омы, `""` — по умолчанию), `listen_until` (до когда она слушает, эпоха в секундах, `null` — не слушает), `listen_secs` (длина этого окна слушания); `struggling` (агентов с 3+ упавшими вызовами за ход), `orb_moods`, `orb_idle_motion`; `rate_now` (темп этого ответа с колеса, `""` — не задан); `news_every` (минуты, `0` — без бюджета), `earcons`, `intonation`; `done_facts`, `permission_buttons`, `agent_inbox`; `wake` (`on`, `off`, `battery`, `muted`, `busy`, `no_model`, `no_mic`), `wake_word`; `memory`. Булевы поля, кроме `media_hold`, — настройки страницы окна; пока функции нет, они `false`, `wake` — `off`, `news_every` — `0`, строки пустые. ## Установка и тесты

`./install.sh` — сборка, сервис `systemd --user`, venv с Silero и voice-venv для Омы, ссылка на плагин. Версии Python-пакетов закреплены: `python/requirements-voice.txt` (в нём и `claude-agent-sdk` со своим claude CLI), `python/requirements-tts.txt`, torch — CPU-сборка из `python/requirements-torch.txt`; повторный запуск приводит venv к ним. Модель Silero `v5_6_ru.pt` (имя файла — `MODEL` в `src/tts.rs`) и Smart Turn проверяются по sha256; прежний `v5_ru.pt` скрипт не удаляет — его можно удалить руками. В v5_6 «*» в тексте включает фокус, а непарная «**» роняет синтез фразы — поэтому подготовка текста убирает все «*» (тест `prepare_drops_every_asterisk`). Служба и Ома обновляются вместе: сразу после слияния — `./install.sh` из той же папки. Ома (`python/agent_voice`) подключена ссылкой и меняется вместе с файлами, а служба — бинарник, который пересобирает и перезапускает только `install.sh`; с перезапуском службы перезапускается и Ома (EOF её stdin). Протокол между ними меняется (`voiced`, `user_paused`): Ома до `voiced` с новой службой застревает в «говорю» — реплика без звука больше не сдвигает `played_at`, а она кончала речь по этому сдвигу. Плагин включается `omarchy plugin enable predmaxim.agent-speak`. Хуки Claude (`~/.claude/settings.json`: `Stop`, `UserPromptSubmit`, `Notification`, `MessageDisplay` → `agent-speak hook <вид>`, `PostToolUse` → `agent-speak hook post-tool-use` — подсказка про лимит, `SessionEnd` → `agent-speak hook session-end` — агент вышел сам, а не упал) и `notify` Codex (`~/.codex/config.toml`) подключаются вручную.
- **Строка статуса** — обёртка в managed-настройках Claude Code, они старше пользовательских. Ставится один раз, нужен root:
  ```sh
  printf '{"statusLine": {"type": "command", "command": "%s statusline"}}\n' ~/.local/bin/agent-speak \
    | sudo install -Dm644 /dev/stdin /etc/claude-code/managed-settings.d/agent-speak.json
  ```
  Проценты лимитов уходят демону. Ввод и вывод — команде `statusLine` из `~/.claude/settings.json` (у автора — скрипт Orca). Пользовательскую `statusLine` обёртка не трогает. Orca переписывает её при каждом своём запуске, если узнаёт там свой скрипт, поэтому обёртка в ней не держится. В `/status` Claude Code появится строка `Enterprise managed settings (file)`. Битый JSON в этом файле не даст Claude Code запуститься. Без root подойдёт и прежний вид, если `statusLine` больше никто не переписывает: `agent-speak statusline <прежняя команда…>`.
- **Codex:** подсказка про лимит — тем же хуком, `PostToolUse` → `agent-speak hook post-tool-use` в `~/.codex/hooks.json`; Codex попросит доверить новый хук.

Тесты: `cargo test`, с моделью — `cargo test -- --ignored` и `python/test_silero_tts.py`; Ома — `~/.local/share/agent-speak/voice-venv/bin/python -m pytest python/test_agent_voice.py`; плагин — `node plugin/test.js`.

Проекты: `docs/superpowers/specs/`.
